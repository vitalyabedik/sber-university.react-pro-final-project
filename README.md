# React PRO — финальный проект

Доработка приложения интернет-магазина: архитектура, оптимизация рендеров, Portal, `useRef`,
альтернативная сборка, React 19 hooks.

Стек: React + TypeScript, Redux Toolkit + RTK Query, React Router v6, React Hook Form + yup, MUI, Webpack.

## 1. Архитектура и структура

## Структура проекта

```text
src/
├── app/            # композиция приложения, глобальные стили
├── pages/          # страницы — только композиция виджетов и фич

│   └── products/   # каталог, поиск, сортировка, лайк, отзывы, инфинит-скролл

├── shared/

│   ├── store/      # Redux Toolkit, RTK Query, слайсы, HOC WithProtection/WithQuery
│   ├── providers/  # роутер
│   ├── api/        # ApiServise
│   ├── assets/
│   ├── types/
│   └── utils/

```

## 2. Оптимизация

Профиль снимался в React DevTools Profiler на главной странице и в корзине: скролл каталога,
лайк товара, изменение количества товара в корзине.

Найденные hotspot'ы:

| Компонент                           | Проблема                                                                                                                                                                                         | Решение                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `CartProductItem` (`features/cart`) | элемент списка корзины не мемоизирован, а `onDelete` создавался заново на каждый рендер — при изменении количества одного товара перерисовывались все строки корзины и вложенные в них `Counter` | `React.memo` + `useCallback` для `handleDelete`                                |
| `AddToCartButton` (`features/cart`) | обработчик клика — inline-стрелка в рендере, `addProductToCart` — новая функция на каждый рендер хука                                                                                            | `React.memo`, `useCallback` на обработчик, `useCallback` внутри `useAddToCart` |
| `Header` (`widgets`)                | `products.filter(...)` пересчитывался на каждом рендере: подписки на RTK Query, стор пользователя и корзину срабатывают при скролле, поиске и любом изменении корзины                            | `useMemo` по `products` и `user?.id`                                           |

Почему так: `React.memo` работает только при стабильных пропсах, поэтому `useCallback` добавлен
именно там, где функция уходит в мемоизированный компонент. `useMemo` — только для вычисления,
которое действительно дорого и повторялось на каждом рендере.

Дополнительно мемоизация не добавлялась в компоненты, которые рендерятся редко или чьи пропсы
и так стабильны (`Card`, `Price`, `CartAmount`, `Rating`), — там `memo` не уменьшает число рендеров.

### Выводы по результатам оптимизации (до / после)

- **Добавление товара:** время рендера сократилось с 1.1 мс до 0.8 мс. Изменение счетчика больше не вызывает каскадный рендер всего списка и родительских компонентов — обновляется только конкретный `CartItem`.
- **Удаление товара:** время рендера снизилось с 0.5 мс до 0.3 мс (на 40%). Область перерисовки сузилась с целого `CartList` до одного компонента `CartItem`.
- **Лайк товара:** время рендера стабильно минимальное (0.1 мс). Клик изолирован: перерисовывается только одна карточка внутри `CardList`, каскадного рендера списка нет.
- **Скролл каталога:** `useMemo` в `Header` сработал как «щит», погасив каскадный рендер сверху вниз. Теперь при скролле перерисовывается только активный `ProductCard`, а не весь список (незначительный рост времени с 2.3 до 2.9 мс — нормальная плата за сравнение мемоизированных значений, которая окупится на больших списках).

**Общий итог:** мемоизация (`React.memo`, `useCallback`, `useMemo`) успешно изолировала обновления. Приложение избавилось от «каскадных» перерисовок целых списков при изменении состояния одного элемента, что критически важно для отзывчивости интерфейса при росте каталога и корзины.

## 3. React.Portal

Модальное окно вынесено в `src/shared/ui/Modal` и рендерится через `ReactDOM.createPortal`
в контейнер `<div id="modal-root"></div>`, добавленный в `public/index.html` рядом с `#root`.
Компонент презентационный: принимает только `isOpen`, `onClose`, `title`, `children` и `className`,
без стора и API.

Способы закрытия:

| Способ                   | Реализация                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| иконка крестика          | кнопка внутри модалки с `aria-label='Закрыть модальное окно'`                                                                |
| клик вне области модалки | `onClick` на overlay с проверкой `event.target === event.currentTarget` — клик по содержимому не считается кликом по overlay |
| клавиша `Escape`         | обработчик на `document` в `useEffect`, снимается при закрытии и размонтировании                                             |

Фокус:

- при открытии элемент, на котором был фокус (триггер), сохраняется в `useRef`, затем фокус
  переводится на кнопку закрытия: `closeButtonRef.current?.focus()`;
- при закрытии в cleanup эффекта фокус возвращается на сохранённый триггер.

Реальный кейс — подтверждение удаления товара из корзины: иконка мусорки в `CartProductItem`
(`src/features/cart`) открывает модалку «Удалить товар из корзины?» с кнопками «Отмена» и
«Удалить». Товар удаляется только после подтверждения, после закрытия фокус возвращается
на иконку мусорки.

## 4. useRef

`useRef` применён в двух сценариях.

Хранение значения между рендерами без перерендера — `features/auth/ui/SignInForm.tsx`:
`failedAttemptsRef` считает неудачные попытки входа. В `catch` инкремент, после успешного входа
сброс в ноль. Значение не выводится и не влияет на разметку, поэтому `useState` здесь дал бы
лишний ререндер формы (и пересоздание полей MUI) на каждую ошибку; `ref` меняет значение без
рендера, а счётчик при этом переживает все последующие рендеры формы.

Работа с DOM:

- `SignInForm` и `SignUpForm` — поля email получили `inputRef` (MUI прокидывает его на `<input>`),
  а `useEffect` при монтировании вызывает `emailInputRef.current?.focus()`: курсор сразу в поле
  «Email Address», при переходе `SignIn` ↔ `SignUp` компонент перемонтируется и фокус ставится заново;

Автофокус сделан через `ref` + `focus()`, а не атрибутом `autoFocus`: правило `jsx-a11y/no-autofocus`
в ESLint запрещает атрибут, а фокус из `useEffect` — это и есть пример взаимодействия с DOM через `ref`.

Проверки: `tsc --noEmit` и `eslint src` проходят, `npm run build` собирается.
